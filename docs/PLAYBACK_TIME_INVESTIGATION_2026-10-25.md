## 代码因果链

1. `components/recording-console.tsx` 的“已选片段”显示当天搜索返回的 `startAt/endAt`；设备会按查询日界截断标签。
2. `server/recordings.ts` 的 `estimateDuration` 查询邻日同文件，只恢复预估总时长，不返回完整起点或偏移。
3. `server/download.ts` 将可信原始 URI 交给 HTTP 下载。历史实机已有整文件下载证据；`server/playback-remux.ts` 从下载内容开头换封装，没有按搜索范围裁剪。
4. `components/hls-video.tsx` 的历史 HLS 使用 `startPosition: 0`，因此从文件开头播放。
5. 全天时间轴点击只调用 `onSelect(segment.id)`，没有计算点击钟表时刻与文件内偏移，也会从所选文件开头起播。

根因是把“当天查询覆盖范围”作为“实际播放文件范围”展示，而播放使用完整文件。用户样例的时间偏移与时长差可由这一组合解释，无需假设统一的时区偏移。

## 用户再次反馈后的复查与当前实现

用户继续反馈所选时间与回放进度不一致，并补充播放器没有显示、看起来像出错。首次修复只补了默认起播偏移，全天轴仍丢弃点击时刻，进度仍是文件内时长；验证只检查 `currentTime` 和解码帧数，没有覆盖完整的钟表选择、实际定位与进度显示，也没有核对被选分片的源时基。本次补齐这些行为及证据，保留 OSD 绝对精度的独立边界。

当前时间链路在数据中分别保存查询覆盖、完整文件范围、目标时刻和实际播放位置；`fileRange.startAt` 用于将钟表时刻转成媒体偏移，同文件重新选择复用现有会话定位。按用户后续明确要求，界面已移除“当日覆盖 / 选定时间 / 完整文件”三行元信息、播放器内第二条进度条和“当日录像”标题。唯一全天时间轴位于播放器容器内，普通与全屏使用同一节点；拖动时显示设备时区的 HH:mm:ss，松手按所在片段定位，无录像时提示并恢复原位置。实际媒体完成定位后，同一游标跟随画面推进；等待目标有明确状态。跨出所选日期时当前时刻补月日，避免将日期外实际位置显示成日界。下载 A/B 仍采用文件内相对偏移，不扩展下载范围。

等待目标不再撤掉整个播放器，而是保留外框和操作入口、暂停并隐藏未定位的画面，显示定位/读取状态，支持取消定位和关闭。文件起点无法确认时明确拒绝钟表定位并释放会话；实际文件不足、加载失败和网络异常有可见错误及重试入口，不能以文件开头替代用户所选时间。

### 媒体分片检查与修复

固定两秒的视频分片可能拆开 GOP，使初始定位恰好从依赖前片的非关键帧片段开始。合成 HEVC 回归已复现：旧参数产生的依赖片单独打开时解码为 0 帧并报错；历史视频现在只沿关键帧边界分片，H.264 和 HEVC 各片独立打开时均可完整解码。此机制可导致“数值到达但画面不出现”；没有保留用户报错时的旧会话，不能倒推其当时必然命中哪一个分片。

历史 HLS 的 `EXTINF`、读取进度与总长同时改用连续 DTS 样本时长。合成 HEVC/B 帧已证明相邻分片 PTS 跨度可重叠：3 秒样本拆为 6 个子 GOP 分片后，旧 PTS 跨度累加为 4.416667 秒，DTS 累加为 3 秒；另一个 25 fps / 12 秒合成样本按原两秒参数产生 12.48 秒 PTS 累加。回归逐片核对 HLS 累计边界与编码 `tfdt` 相对文件首 DTS 的位置，避免只验证播放器数值。该漏洞与用户样例是否触发需分别判断，下面真实样本的旧 PTS 累计差为零。
