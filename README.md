# 海康 NVR 网页客户端

在浏览器里看海康录像机的实时画面、查历史录像，也可以把正在看的通道或需要的录像片段保存到电脑，不用安装 ActiveX 插件。

录像机继续按原来的方式录像和存储。这个项目提供查看和本地保存功能，除用户主动保存通道名称外，不修改其他设备设置，也不删除设备上的录像。

目前仍在开发中，**还没有网页登录和访问权限控制，只适合在受信任的本机或局域网使用，不要直接开放到公网。**

## 现在能做什么

- **修改通道名**：在实时页通道右侧点击铅笔，输入新名称后保存到 NVR；设备账号需要相应配置权限。
- **看实时画面**：支持 1、2、4、8、16 分屏，每个窗口可以单独选择摄像头，从画面中央开始预览，连接和缓冲时显示加载图标。
- **查历史录像**：按摄像头和日期查询，从画面中央开始播放；播放器内全天时间轴是唯一回放进度条，拖动时显示目标时刻，松手后定位并播放；支持声音和 0.25–4 倍速。
- **录下实时画面**：选择保存位置后开始录制，可以手动停止，也可以设置 15、30 或 60 分钟后自动结束。
- **下载需要的片段**：在当前录像文件里标记起点和终点，保存这一段。下载结果保持原速，不受播放器倍速、暂停或静音影响。

支持 H.264 和 H.265 视频。H.265 能否播放取决于浏览器和操作系统的解码能力；遇到不支持的环境，不会自动改用服务端转码。

## 先运行起来

### 准备环境

运行这套应用的电脑需要：

- Node.js 20.9 或更新版本，以及 pnpm。
- FFmpeg，安装后能在命令行执行 `ffmpeg`。它用于实时预览、历史回放和实时录制；只查询通道和录像列表时不需要。
- 能连接到录像机的网络，以及有相应查看权限的设备账号。

FFmpeg 安装在**运行应用的电脑**上，浏览器所在电脑不需要另外安装。`ffprobe` 只用于诊断和验证，日常播放、保存不依赖它。

### 填写设备信息

在项目目录执行：

```sh
pnpm install
cp -n .env.example .env
```

`cp -n` 会保留已有的 `.env`。打开 `.env`，至少填好以下三项：

| 配置项         | 填什么                                                 |
| -------------- | ------------------------------------------------------ |
| `NVR_HOST`     | 录像机的 IP 或主机名，不要加 `http://`、路径或账号密码 |
| `NVR_USERNAME` | 录像机账号                                             |
| `NVR_PASSWORD` | 录像机密码                                             |

其他配置通常可以先用默认值：HTTP 端口 `80`、RTSP 端口 `554`、时区 `Asia/Shanghai`。页面上的查询日期和录像时间默认按北京时间显示。

`NVR_RECORDING_TIME_MODE` 默认是 `device-local`，用于适配已测试设备的录像时间格式；采用标准 UTC 时间格式的固件可改为 `utc`。完整配置见 [.env.example](.env.example)。修改配置后需要重启应用。

设备账号密码只在服务端读取。不要把填写过的 `.env` 提交到仓库或发给别人。

### 启动

```sh
pnpm dev
```

启动后打开终端显示的地址，通常是 [http://localhost:3000](http://localhost:3000)。如果 3000 端口被占用，开发服务器可能使用其他端口，以终端输出为准。

同一局域网的其他电脑可以用运行应用那台电脑的 IP 和实际端口访问。**但要在其他电脑上录制或下载，还需要 HTTPS；普通的局域网 HTTP 地址不满足浏览器写文件所需的条件。** 本机使用 `http://localhost` 可以保存。

需要运行生产构建时，先停止开发服务器，再执行：

```sh
pnpm build
pnpm start
```

只需启动这一个应用，不用另外启动 API 服务。生产构建并不代表登录、HTTPS 和部署工作已经完成。

## 怎么用

### 看实时画面

首页默认显示四个窗口。选中窗口后，从左侧通道列表或窗口里的选择框分配摄像头，再点击画面中央的播放按钮。连接和首次缓冲期间会显示旋转的加载图标；也可以用顶部的“全部开始”开启已分配的窗口。

进入页面、添加窗口都不会自动取流。每个窗口可以单独停止、开启声音或全屏；切换通道、减少分屏或离开实时页时，对应预览会停止。

目前每次实时预览最长持续 10 分钟，到期后需要重新开始预览。独立的录制任务不受这个预览时限影响。

### 用 URL 保留页面选择

页面已接入 nuqs。复制当前地址、添加书签或刷新页面，可以恢复地址中记录的状态：

| 页面 | 参数 | 含义 |
| --- | --- | --- |
| 回放 | `track`、`date`、`zoom` | 摄像头轨道、设备时区下的查询日期、时间轴缩放（1 / 2 / 4） |
| 实时 | `layout`、`window`、`sidebar`、`slots` | 分屏（1 / 2 / 4 / 8 / 16）、当前窗口（从 1 开始）、通道栏是否展开、窗口通道分配 |

例如 `/playback?track=201&date=2026-10-24&zoom=2` 会打开对应通道和日期，以 2 倍时间轴显示。`/?layout=2&slots=1:201,2:101&sidebar=false` 会恢复双窗口分配并收起通道栏；`slots` 中 `3:0` 表示窗口 3 不分配通道。

切换回放摄像头或日期可以用浏览器前进/后退恢复；调整缩放、分屏、通道栏和实时窗口只替换当前历史项。默认值通常省略；未指定日期和通道时，仍使用设备时区的今日及第一个可用通道。切换查询或缩放后会把当前实际通道和日期一起写入地址，方便分享固定查询。

非法参数回退到默认状态；设备已移除的回放通道回退到首个可用通道，实时窗口的失效通道显示未分配。URL 不记录设备地址、账号密码、媒体 URI、会话、录像片段选择、声音或录制任务；打开链接和刷新均不会自动开始取流。页面顶部导航打开另一页的默认地址，需要保留当前选择时可复制完整 URL 或通过浏览器后退返回。

### 修改通道名称

点击通道旁的铅笔按钮，输入新名称后点击“保存”。当前保守限制为 1–32 个 UTF-8 字节，中文通常每字占 3 字节；首尾空白会移除。保存期间禁止重复提交，失败时保留输入并提示原因。名称从设备读回确认后，实时与回放页面共用的通道列表会重新读取。

修改的是 NVR 数字通道配置名称，不额外修改视频画面中的 OSD 叠字。当前已通过模拟接口的自动测试及实机只读配置检查，真实设备写入和持久化仍待验证。

服务端入口为 `PUT /api/channels/:trackId/name`，JSON 只接受 `{ "name": "新名称" }`。服务端通过真实 `SrcChannel` 映射定位 `/ISAPI/ContentMgmt/InputProxy/channels/<ID>`，GET 原配置、保留其他字段、PUT 修改名称后再次 GET 确认。映射缺失时拒绝操作；不接受设备地址或完整 XML。

### 录下实时画面

点击窗口中的“录制”，选择录制时长和保存位置。默认录制 30 分钟，也可以随时点击“停止并保存”。

录制一旦开始，就固定录制原来的通道。切换到其他通道、调整分屏、停止预览，或在应用内切到回放页，都不会停止它。短暂切到其他浏览器标签页也可以继续录制。顶部“录制与下载”和页面中的任务状态条会显示进度，可以在那里停止原通道的录制。

支持保存到文件夹时，录制会约每 5 分钟保存成一个文件，停止时完成最后一段。使用单文件保存或 Safari 原生下载时，会保存为一个文件。同一页面最多同时进行 4 个录制或下载任务。

**录制期间请保持网页打开，并让电脑保持唤醒。** 刷新或关闭网页、退出浏览器、网页被冻结、电脑休眠，都可能中断录制。离开提示和最后的保存只能尽力完成；重新打开网页不会自动恢复任务。已经完成的分段会保留，尚未完成的文件不保证能恢复。

### 查录像、下载片段

1. 打开“录像回放”，选择摄像头和日期。
2. 点击画面中央的播放按钮，从当天第一个录像片段开始；也可以在播放器内的全天时间轴上点击或拖动到要回看的时刻，松手后直接定位并播放，暂停或尚未开始时也一样。片段列表选片后直接播放，同一文件内定位复用现有回放。
3. 找到需要的内容后，点击“下载片段”，设置起点和终点，再选择保存位置。

下载选区的起点和终点是**当前文件内的位置**。例如 `02:00` 到 `03:00`，表示文件开始后的第 2 分钟到第 3 分钟，不是北京时间凌晨 2 点到 3 点。可以用当前位置标记，也可以输入 `分:秒` 或 `时:分:秒`；文件总长确认后，还可以拖动选区。

为了让保存的视频正常播放，实际保存范围可能比选区前后多出一点，任务会显示实际覆盖范围。下载开始后，切换摄像头、日期、文件或关闭回放，不影响已经提交的下载任务。

下载始终保持原速；原录像有声音且格式受支持时，也会保留声音。即使播放时开了 4 倍速、暂停或静音，也不会改变下载的内容。目前下载只支持当前文件内的片段，不支持跨文件、跨日下载，也不能按北京时间精确指定下载起止时刻。

播放回放时点击画面可暂停，暂停后点击中央按钮继续。连接、缓冲和定位时显示加载图标；打开页面仍不会自动取流。当前片段播放结束且确认读取完整后，会先释放旧会话，再自动播放当天下一片段，保留倍速和声音偏好；有缺口时提示，到当天最后一段结束后停止。关闭回放、切换查询或播放失败会取消推进，无需设置连续播放开关。

回放只保留播放器内一条全天时间轴：播放时游标跟随当前画面时间，拖动时显示目标时刻，松手后定位并播放；没有录像的时段会提示并保留当前位置。全屏时使用同一条时间轴。界面不再重复显示当日覆盖、选定时间和完整文件范围，媒体仍按服务端恢复的完整文件起点计算偏移。目标未读取到时保留播放器外框和等待/取消入口；无法确认文件时间时明确报错。钟表映射依据设备文件标签，画面 OSD 与标签的秒级精度和原生 Safari 联动仍待验收。下载选区继续使用文件内相对时间。

## 保存下来的文件

录制和片段下载都保存为 **MKV**，保留 H.264 / H.265 原始视频和受支持的 G.711 音轨，不重新压缩画面。不支持的音轨可能无法保存，这时任务会提示“部分保存”。可以用 VLC、IINA 等兼容播放器打开文件。

保存时边接收、边处理、边写入磁盘，不会先把整段录像攒进浏览器内存再下载。浏览器和系统仍会使用内存缓冲或本机临时文件。

服务端负责连接录像机和转发数据，实时流还需要 FFmpeg 转换传输格式；录制和下载成品由浏览器生成。**历史回放为了支持拖动进度，仍会在服务端保留受控的临时分片**，关闭或到期后清理。

如果设备只能从文件开头顺序读取，下载靠后的片段仍需要先读取前面的内容，所以选择短片段不一定马上开始写入，也不代表网络只传输所选的那一小段。

Safari 等使用浏览器原生下载的路径，在应用显示“传送完成”后，还需要到浏览器下载列表确认文件已经完成。部分播放器可能不能立即显示这类 MKV 的总时长，拖动定位的兼容性也会有所不同。

## 兼容性和目前的限制

实机测试使用海康 `DS-7816NB-K2/16P`、固件 `V4.30.000`。其他型号和固件需要单独确认。

| 浏览器        | 已验证的范围                                                                                                                                                         |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 桌面 Chrome   | 真实设备的实时预览、整段回放、录制和片段下载；已验证 30 分钟单路录制、5 分钟分段，以及双路录制分别停止。                                                             |
| Safari 27.0.1 | 已验证短时间录制、片段下载、取消，以及录制中切通道、分屏、应用页面和短暂切到后台。完整的播放、声音、进度跳转和全屏功能组合还没有全部验收，长时间、多路保存也待验证。 |
| Edge          | 尚未单独实测。                                                                                                                                                       |

另外还有这些限制：

- 界面支持 16 分屏，但不代表已经验证 16 路真实摄像头同时稳定播放；实际效果还受设备取流能力、网络和电脑解码性能影响。
- 60 分钟录制、多路长时间保存、休眠或崩溃后的文件情况仍待验证。浏览器录制适合临时留存，持续录像仍由 NVR 负责。
- 历史回放目前通过设备的 HTTP 文件下载接口实现，标准历史 RTSP 路径还没有打通。当前默认在片段结束后自动衔接下一片段，真实文件切换和长期稳定性仍待验收，不能保证文件之间无缝衔接。

## 继续开发

项目使用 Next.js、React、TypeScript 和 Hono，前后端在同一个 Next.js 应用里运行。页面在 `app/`，界面组件在 `components/`，设备接口和媒体服务在 `server/`，共享数据约定在 `shared/`。

常用检查命令：

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm test:e2e
```

浏览器测试默认使用模拟数据。已有开发服务器时，用 `TEST_BASE_URL` 指向它，避免重复启动造成冲突；未指定时，测试会自行启动 3100 端口。真实设备测试需要另行开启，具体命令和已验证范围见下方文档。
