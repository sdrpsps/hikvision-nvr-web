# 海康威视 NVR 网页客户端 · Hikvision NVR Web

[简体中文](README.md) | [English](README.en.md)

在浏览器中查看海康威视录像机的实时画面和历史录像，录制实时画面或下载录像片段，无需安装 ActiveX 插件。录像仍由 NVR 负责；除主动修改通道名称外，应用不会修改设备设置或删除录像。

**应用没有网页登录。** 能访问应用的人都可以使用它，请只在受信任的本机或局域网中运行。设备凭据只在服务端配置，不需要在网页输入。

## 为什么做这个项目

起因很简单：我想在 macOS 上查看海康威视录像机的视频回放，但网页回放需要安装插件，而插件只有 Windows 版本。

macOS 上的海康客户端也已经很久没有更新，版本太老。我在 GitHub 上找了一圈，也没有找到适合自己需求的项目，干脆就自己做一个，让 macOS 也能直接用浏览器看实时画面、查历史录像、保存需要的片段，不再依赖 Windows 插件。

## 功能

- 实时查看 1、2、4、8 或 16 个画面，可分别选择通道、开启声音和全屏。
- 按摄像头和日期查询录像，通过全天时间轴定位，支持声音和 0.25–4 倍速。
- 录制实时画面，或下载当前录像文件中的片段，保存为 MKV。
- 修改 NVR 通道名称，设备账号需有相应配置权限。

支持 H.264 和 H.265；H.265 播放取决于浏览器和操作系统的解码能力，不支持时不会自动转码。界面为中文。

## 运行应用

### 使用 Docker（推荐）

安装并启动 Docker，确保运行应用的电脑可以连接录像机。将下面的录像机地址、账号和密码替换为实际值，然后启动容器：

```sh
docker run -d --name hikvision-nvr-web --restart unless-stopped \
  -p 3000:3000 \
  -e NVR_HOST=录像机地址 \
  -e NVR_USERNAME=录像机账号 \
  -e NVR_PASSWORD=录像机密码 \
  ghcr.io/sdrpsps/hikvision-nvr-web:latest
```

`NVR_HOST` 只填写 IP 或主机名，不含协议、路径和账号密码。打开 [http://localhost:3000](http://localhost:3000)。镜像已包含 FFmpeg；修改设备配置后需要重新创建容器。容器需要能访问 NVR 的 HTTP、RTSP 和设备支持的回放端口，并为历史回放临时文件留出足够空间。

默认 HTTP 端口为 `80`、RTSP 端口为 `554`，查询和显示时区为 `Asia/Shanghai`。`NVR_RECORDING_TIME_MODE` 默认 `device-local`，适配已测试设备的录像时间格式；使用标准 UTC 时间格式的固件可设为 `utc`。其他配置见 [.env.example](.env.example)，可通过添加 `-e` 参数传入。

### 从源码运行

运行应用的电脑需要 Node.js 24、pnpm 11、可在命令行执行的 FFmpeg，以及连接 NVR 的网络和有查看权限的设备账号。FFmpeg 安装在应用服务器上，单独用来访问网页的电脑不需要安装；`ffprobe` 仅用于诊断。

在项目目录安装依赖并创建配置：

```sh
pnpm install
cp -n .env.example .env
```

`cp -n` 不会覆盖已有配置。Windows PowerShell 可改用 `if (-not (Test-Path .env)) { Copy-Item .env.example .env }`。编辑 `.env`，至少填写：

| 配置项 | 填写内容 |
| --- | --- |
| `NVR_HOST` | NVR 的 IP 或主机名，不含协议、路径和账号密码 |
| `NVR_USERNAME` | 设备账号 |
| `NVR_PASSWORD` | 设备密码 |

其他配置见 [.env.example](.env.example)，修改后重启应用。不要提交或分享填写过的 `.env`。

启动开发服务器：

```sh
pnpm dev
```

打开终端显示的地址，通常是 [http://localhost:3000](http://localhost:3000)；端口被占用时以终端输出为准。生产运行可先停止开发服务器，再执行 `pnpm build` 和 `pnpm start`，无需单独启动 API 服务。

### 从其他电脑访问

局域网内可使用运行应用的电脑的 IP 和实际端口访问。**在其他电脑上录制或下载需要 HTTPS**；本机 `http://localhost` 可以保存。HTTPS 和反向代理需自行配置。应用没有登录认证，若限制网络访问，应同时保护页面、API 和媒体资源，也不要将 NVR 管理或 RTSP 端口直接公开到互联网。

## 使用

### 实时查看和录制

首页默认显示四个窗口。选择窗口，从通道列表或窗口选择框分配摄像头，然后点击画面中央的播放按钮；“全部开始”可开启所有已分配窗口。打开页面或添加窗口不会自动取流。切换通道、减少分屏或离开实时页会停止相应预览；每次预览最长 10 分钟，到期后可重新开始。

点击窗口中的“录制”，选择保存位置和时长；默认 30 分钟，也可选 15 或 60 分钟，或手动停止并保存。录制固定使用开始时的通道，切换通道、分屏、停止预览或在应用内切换页面不会停止任务，可通过“录制与下载”查看进度或停止。

支持保存到文件夹时，录制约每 5 分钟生成一个文件；单文件保存和 Safari 原生下载保存为一个文件。同一页面最多同时运行 4 个录制或下载任务。**录制期间请保持网页打开、电脑唤醒**：刷新、关闭网页、浏览器冻结或电脑休眠可能中断任务，重新打开不会自动恢复；已完成的分段保留，未完成文件不保证恢复。

点击通道旁的铅笔可修改名称，名称限制为 1–32 个 UTF-8 字节，首尾空白会移除；中文通常每字占 3 字节。修改的是 NVR 通道名称，不会额外修改画面中的 OSD 叠字。

### 回放和下载片段

1. 打开“录像回放”，选择摄像头和日期。
2. 点击画面中央按钮播放当天第一段录像，或在播放器内的全天时间轴上点击、拖动到目标时刻；也可从片段列表选择。没有录像的时段会提示。播放完已完整读取的片段后，会自动播放当天下一段；片段间有缺口时会提示，到最后一段后停止。
3. 点击“下载片段”，设置起止时间并选择保存位置。可使用时分秒选择器或当前位置标记，文件时长确认后也可拖动选区。

回放可调整速度和声音，点击画面暂停；键盘 `←` / `→` 按设定步长定位，默认 0.5 秒，可在“步长”面板调整为 0.1–2 秒。回放默认开启声音；若浏览器阻止声音或音轨不受支持，画面仍可播放。实时预览默认静音。

下载范围限于**当前查询日期内的当前录像文件**，不支持跨日或跨文件拼接。为保证播放，实际保存范围可能因关键帧略有扩展，任务会显示实际覆盖范围。文件保持原速，播放时的倍速、暂停和静音不影响成品；下载开始后切换查询或关闭回放也不会停止任务。设备录像时间与画面 OSD 的绝对精度尚未校准。

支持 SHTTP 按时间回放的设备可从目标附近开始读取；设备不支持时使用 HTTP 文件回放，跳到较晚位置可能需要等待之前的内容读取完毕。片段下载仍通过原文件读取，靠后的短片段也可能需要等待，且网络传输量可能大于选区。自动衔接的真实文件切换及长期稳定性仍待验证，不能保证无缝衔接。

### 保存文件和页面选择

录制和下载保存为 **MKV**，保留原始 H.264/H.265 视频及受支持的 G.711 音轨，不重新压缩画面。不支持的音轨可能被省略，任务会提示“部分保存”；可使用 VLC、IINA 等播放器打开。Safari 等浏览器的原生下载显示“传送完成”后，还需在浏览器下载列表确认文件已完成；部分播放器可能无法立即显示总时长或顺畅定位。

保存过程中浏览器边接收边写入；历史回放为支持定位，会在服务端使用受控临时分片，并在关闭或到期后清理。

复制或收藏当前页面地址可以保留通道、日期、时间轴缩放、分屏和通道栏等页面选择；打开链接或刷新不会自动取流。地址不包含设备凭据、媒体地址或录制任务。浏览器前进和后退可恢复回放摄像头和日期的切换；导航到另一页面会打开该页面的默认地址。

## 兼容性和限制

实机测试使用海康 `DS-7816NB-K2/16P`、固件 `V4.30.000`；其他型号和固件需要单独确认。

| 浏览器 | 已验证范围 |
| --- | --- |
| 桌面 Chrome | 实时预览、整段回放、录制和片段下载；SHTTP 文件末尾附近起播、同文件再次定位及会话释放；30 分钟单路录制、5 分钟分段及双路录制分别停止。 |
| Safari 27.0.1 | 单路 HEVC 短时直播，以及短时间录制、片段下载、取消、保存期间切通道、分屏、应用导航和短暂后台。完整回放与声音、跳转、全屏的组合，以及长时间、多路保存仍待验证。 |
| Edge | 尚未单独实测。 |

16 分屏不代表已验证 16 路同时稳定播放，效果取决于设备、网络和电脑性能。60 分钟录制、多路长时间保存及休眠或崩溃后的文件恢复仍待验证。通道改名已通过模拟测试及实机只读检查，**真实设备写入和持久化尚未验证**。

## 开发与发布

项目使用 Next.js、React、TypeScript 和 Hono，前后端运行在同一个应用中。开发约定见 [AGENTS.md](AGENTS.md)。常用检查：

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm test:e2e
```

浏览器测试默认使用模拟数据；可通过 `TEST_BASE_URL` 复用已有开发服务器，否则测试会启动 3100 端口。真实设备测试需显式启用，具体条件见 `tests/browser/`。

推送到 `main` 后，Release Please 根据提交记录创建或更新发布 PR；合并后创建 GitHub Release 和版本标签，并发布 Docker 镜像。手动推送的版本标签须与 `package.json` 中的版本一致。首次发布和工作流配置可参考仓库的 [发布工作流](.github/workflows/release.yml)和[镜像工作流](.github/workflows/docker-publish.yml)。
